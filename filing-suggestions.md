# How every routine files a suggestion

**This file is the single set of rules. Every routine reads it before filing.** Change it here and
every routine changes with it. Never copy these rules into a runbook.

## Where suggestions go

One place, for every routine: Adam's **Claude projects** database in Notion.

Data source: `collection://3bcbadef-0938-800d-b406-000bef206230`

Go straight there. **Never search Notion for it** — searching turns up Adam's private pages, and
reading those has crashed a run.

Nothing goes in a spreadsheet. Both old ✨ Suggestions tabs are deleted.

## Most runs file nothing

**Nothing is the normal, correct answer.** A quiet run is a good run.

A suggestion only goes in if it clears all five:

- **It came from this run.** Something that actually happened, with proof you can point at. Never a
  general idea, never something you thought of while reading the runbook.
- **It is not already your own instruction.** Restating a rule you already follow is not a
  suggestion.
- **It is specific.** Name the file, the command, or the rule that should change. "Improve the
  prompt" is not a suggestion.
- **It is not a one-off.** Something that happened once gets fixed there and then, never turned
  into a rule Adam has to keep feeding.
- **It is not already filed.** Read the rows first. A row with anything written in Adam's decision
  column, or with its tickbox ticked, is finished. Never raise it again, and never re-raise one he
  turned down.

## How to write one

**Two or three sentences. Never more than about 60 words.**

Adam reads these in a list. A wall of text is harder to act on, not more convincing. Say what
should change and the one fact behind it, then stop.

Cut: the date, the order number, the row number, the customer's name, how long it took, how it
felt. Keep a number only when the number **is** the change.

One thing per row. Two separate ideas are two rows, so he can take one and drop the other.

## Which columns you write

Work them out every time. **Never hardcode a column name** — Adam renames and reorders them
whenever he likes.

| What you need | How to find it, whatever it is called |
| --- | --- |
| where the suggestion text goes | The **title** column. A database has exactly one, so it is never ambiguous. |
| which routine it is about | The **pick-list** whose choices include your routine's name. Pick that choice exactly as written. |

**Never add a new choice** to the pick-list. A new choice files your suggestion under a name
belonging to nobody.

**Every other column is Adam's.** Never write one. Never edit another row. Never tick another
row's box.

The one exception: you may tick the box on **a row you actually finished in this run**. If you are
not certain it is the right row, leave it. Telling him something is done when it is not is worse
than not ticking at all.

## If the database has changed shape

No title column, or no pick-list choice naming your routine? Put the suggestions in your report,
say plainly that you could not file them, and file nothing.
